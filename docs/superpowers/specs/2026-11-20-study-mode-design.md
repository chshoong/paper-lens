# Paper Lens 공부 모드 설계 (논문 + 노트 + 채팅 설명)

작성일: 2026-11-20

## 1. 의도와 이유

사용자는 논문을 읽을 때 **직접 쓰면서 이해하는 사람**이다. 지금은 논문(Paper Lens 리더), Claude 채팅, 번역, 노션을 여러 창에 띄워두고 오가며 공부한다. 창이 흩어져 있어서 화면 배분이 비효율적이다.

원하는 것은 Claude 앱 안에서 이 흐름을 한곳에 모으는 것이다.
- 논문을 한쪽에 띄워두고, 거기서 번역도 된다.
- Claude가 **1장부터 차례로 쉽게 설명한 내용**이 채팅에 이어서 쌓인다. 설명은 **사용자가 읽는 속도에 맞춰** 한 절씩 진행된다.
- 사용자가 **자기 노트**를 따로 쓴다. 노트에는 **LaTeX 수식**을 많이 쓴다. 수식은 직접 쓰기도 하고, 논문의 수식을 옮겨 오기도 한다.

사용자에게 가장 중요한 것은 **Claude와의 대화**이고, 그 대화가 길게 기억되기를 원한다. 그래서 설명은 페이지 안이 아니라 Claude Code 채팅(세션)에서 한다(5절, 방식 2).

## 2. 목표 / 비목표 / 반목표

**목표**
- 큰 모니터에서 논문 PDF, 내 노트, Claude 채팅을 한 화면에 두고 공부할 수 있다.
- 노트에 LaTeX 수식(`$...$`, `$$...$$`)을 쓰면 바로 수식으로 보인다.
- 논문 수식 영역을 캡처하면 LaTeX로 바뀌어 노트에 들어간다. 출처(쪽, 식 번호)도 함께 들어간다.
- 페이지에서 고른 문장이나 캡처를 버튼 하나로 채팅의 Claude에게 넘길 수 있다.
- 채팅에서 Claude가 "이거 노트에 넣어줘" 같은 요청을 받으면 노트에 직접 써 넣을 수 있다.
- 노트는 Paper Lens 안(논문 페이지별)에 잃어버리지 않게 저장되고, 필요할 때 Markdown(+LaTeX)으로 내보낼 수 있다.

**비목표 (이번에는 하지 않음)**
- 노션 자동 동기화. Markdown 내보내기로 충분하다. 노션 내보내기는 나중에 따로 한다.
- 노트를 다른 사람과 같이 쓰기, 공유.
- 손글씨나 펜 입력.
- 쪽 전체를 원문 그대로 통번역하기. 저작권 때문에 Claude가 거절하므로 지금처럼 쪽별 정리와 문단 번역을 유지한다.
- 페이지 안에서 긴 대화하기. 긴 대화는 채팅이 맡는다.

**반목표 (기술적으로 동작해도 실패인 경우)**
- 노트가 사라지는 것. 브라우저 저장소만 쓰다가 날아가는 경우가 여기에 해당한다.
- 수식을 썼는데 깨지거나 원문 그대로만 보이는 것.
- 노트 칸이 좁아서 쓰기 불편한 것.
- 채팅의 Claude가 사용자가 지금 어디를 읽고 있는지 몰라서 매번 다시 설명해야 하는 것.

## 3. 제약

- **Artifact 보안 정책(CSP)**: 외부 스크립트는 cdnjs, jsdelivr, unpkg 등에서만 불러올 수 있다. 외부 스타일시트는 Google Fonts만 된다. fetch로 외부 주소를 부를 수 없다. KaTeX는 CSS와 폰트 파일이 필요해서 그대로는 깨진다. **MathJax 3의 SVG 출력(`tex-svg-full`)**은 CSS와 폰트 없이 스크립트 하나로 동작한다.
- **페이지 안 Claude(`sample` 기능)**: 대화를 기억하지 못한다. 그래서 짧은 일만 맡긴다. 드래그 번역, 쪽별 정리, 수식 캡처를 LaTeX로 바꾸기가 여기에 해당한다.
- **페이지에서 채팅으로 보내기**: `room.sendToClaudeSession(data, {deliver})`는 사용자가 클릭했을 때만 호출할 수 있다. JSON만 보낼 수 있고 최대 4KiB다. 이미지는 직접 못 보내므로 `assets`로 올린 뒤 그 id를 보낸다. `room.presence()`로 사용자가 지금 보는 위치를 공개하면, 플랫폼이 옆 채팅에 그 정보를 데이터로 넘겨줄 수 있다(필수 동작은 아니다). `room`을 쓸 수 없는 화면도 있으므로 대체 경로가 필요하다.
- **저장(`db` 기능)**: 데이터는 Artifact(논문 페이지)마다 따로 있다. 채팅의 Claude는 `ArtifactData` 도구로 같은 데이터를 읽고 쓸 수 있다. 페이지는 `onSnapshot`으로 변경을 실시간으로 받는다. 논문 페이지는 비공개(소유자만)다.
- **논문 PDF 원본 위치**: 채팅의 Claude가 다음 세션에서도 PDF를 직접 읽어야 한다. 그래서 스크래치패드 같은 임시 폴더가 아니라 오래 남는 폴더에 두어야 한다.
- **저작권**: 설명, 요약, 짧은 발췌 번역은 괜찮다. 통번역은 하지 않는다.

## 4. 접근 방식

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 1. 페이지 안에서 전부 | 논문, 설명, 노트 세 칸을 모두 페이지 안에 둔다. 설명은 페이지 안 Claude가 한다. | 고른 세 칸 화면이 그대로 나온다. 다시 열어도 모든 기록이 페이지에 있다. | 페이지 안 Claude는 대화를 기억하지 못해서 긴 토론에 약하다. |
| **2. 논문과 노트는 페이지, 설명은 채팅 (선택)** | 페이지에는 논문과 노트를 두고, 설명과 질문은 앱의 Claude Code 채팅에서 한다. 채팅의 Claude는 노트를 읽고 쓸 수 있다. | 대화를 길게 기억한다. PDF 전체를 직접 보고 깊게 설명할 수 있다. 노트에 직접 써 줄 수 있다. | 화면 배치가 앱의 채팅 창과 페이지 창 배치에 따라 달라진다. 설명 기록이 세션마다 흩어질 수 있다(6.6절에서 보완). |

사용자는 **방식 2**를 골랐다. "너랑 채팅하는 게 중요하고 길게 기억하는 게 낫다. 배치는 살짝 달라져도 괜찮다"는 이유다. 처음 고른 화면 시안은 세 칸 나란히(논문 | 설명 | 노트)였고, 방식 2에서는 이것을 **[앱 채팅 창] + [페이지: 논문 | 노트]**로 구현한다.

## 5. 사용자가 정한 것

- 화면: 큰 모니터 기준, 논문과 설명과 노트를 나란히 둔다.
- 설명: 채팅(Claude Code 세션)에서 읽는 속도에 맞춰 한 절씩 진행한다.
- 노트: Paper Lens 안에 저장하고 나중에 필요하면 내보낸다.
- 노트 수식: LaTeX로 직접 쓰고, 논문 수식을 가져와 넣을 수도 있다.

## 6. 설계 (표시가 없는 항목은 설계자 판단이며, 사용자가 고칠 수 있다)

### 6.1 화면 구성
```
[Claude 앱 채팅 창]  │  [논문 페이지 (Artifact)]
                     │  ┌──── 논문 PDF ────┬──── 오른쪽 패널 ────┐
 Claude: 3.2절 어텐션 │  │ (확대, 드래그,     │ [노트] 쪽별정리 요약 용어│
 쉽게 보면…           │  │  영역 캡처)        │ ## Scaled dot-product │
 나: 왜 루트야?       │  │                    │ $$\mathrm{softmax}…$$ │
                     │  └───────────────────┴──────────────────────┘
```
- 페이지는 두 칸이다. 왼쪽은 PDF, 오른쪽은 탭 패널이다. **기본 탭은 "노트"**이고, 나머지 탭은 쪽별 정리, 요약, 용어다. 기존의 "질문" 탭은 없앤다. 질문은 채팅에서 한다.
- 두 칸 사이 경계는 끌어서 조절한다. 노트가 좁지 않도록 오른쪽 패널의 기본 폭을 지금보다 넓게(화면의 45% 정도) 잡는다.
- 기존 기능은 그대로 둔다: 확대, 쪽별 정리, 요약, 용어, 영역 캡처, PDF 위 하이라이트.
- **드래그 툴바 정리 (설계자 판단)**: 설명은 채팅이 맡으므로 툴바를 다음과 같이 바꾼다.
  - **번역**: 페이지 안 Claude(빠른 모델)가 처리하고, 결과는 선택 영역 옆 작은 팝오버에 띄운다. 팝오버에는 "노트에 넣기" 버튼을 둔다.
  - **설명 / 쉽게 풀기 / 왜 중요해?**: 채팅으로 보낸다. 미리 정한 질문과 함께 `deliver: "send"`로 보내며, 사용자가 확인 창에서 보내기를 누르면 채팅의 Claude가 바로 답한다.
  - **Claude에게 묻기**: 직접 질문할 때 쓴다. 채팅 입력창에 첨부로 올린다(`deliver: "stage"`).
  - **노트에 인용 / 하이라이트**: 노트에 저장한다(6.3절).
- 영역 캡처 툴바: LaTeX로 노트에, 그림을 노트에, 그림·표 해석(채팅으로 보냄), Claude에게 묻기.

### 6.2 노트 편집기
- **블록 방식**이다(노션과 비슷하다). 노트는 블록이 차례로 쌓인 목록이다.
- 블록 종류는 다음과 같다.
  - `text`: Markdown 문단. 굵게, 목록, 제목, 인라인 코드, **인라인 수식 `$...$`**를 쓸 수 있다.
  - `math`: 수식 블록(`$$...$$`). 선택 사항으로 출처(쪽, 식 번호)를 단다.
  - `quote`: 논문에서 가져온 인용문. 출처 쪽 번호가 붙고, 누르면 그 쪽으로 이동한다.
  - `image`: 캡처한 그림. 에셋 id로 저장한다.
- 블록을 누르면 원문(Markdown/LaTeX)을 고치는 상태가 되고, 다른 곳을 누르면 렌더링된 모습으로 돌아간다.
- 수식 블록은 고치는 동안 바로 아래에 실시간 미리보기를 보여준다. 문법이 틀리면 붉은 안내를 보여주고, 원문은 그대로 둔다.
- 키보드: Enter는 새 블록, Shift+Enter는 블록 안 줄바꿈, 빈 블록에서 `$$` 입력은 수식 블록으로 바꾸기, Backspace로 빈 블록 지우기, 블록 끌어서 순서 바꾸기.
- 블록 메뉴: 위아래로 옮기기, 지우기, 종류 바꾸기, "Claude에게 묻기"(6.4절).
- 수식 렌더링은 MathJax 3 `tex-svg-full`(cdnjs, 버전 고정)로 한다.

### 6.3 논문 수식 → 노트
- 영역 캡처 툴바에 **"LaTeX로 노트에"** 버튼을 추가한다.
  1. 캡처 이미지를 페이지 안 Claude(`sample`, images)에 보낸다. "LaTeX만 JSON으로 달라"고 요청한다. 응답 형식은 `{latex, eqNumber?}`다.
  2. 노트 끝(또는 지금 편집 중인 블록 바로 아래)에 `math` 블록을 넣는다. 출처는 `p.N (식 k)`다.
  3. 넣은 블록은 바로 편집 상태로 열어서, 사용자가 확인하고 고칠 수 있게 한다.
- 드래그로 고른 텍스트 툴바에는 **"노트에 인용"**을 추가한다. 쪽 번호가 붙은 `quote` 블록이 들어간다. 이때 고른 영역 위치(`rects`)도 함께 저장해서 PDF 위에 형광펜 표시를 남긴다. 기존 "하이라이트" 버튼은 이 동작과 같다(설계자 판단: 기존 하이라이트가 사라지지 않게 하려는 것).
- 캡처 툴바에는 **"그림을 노트에"**도 추가한다. 이미지를 `assets`에 올린 뒤 `image` 블록으로 넣는다.

### 6.4 페이지 → 채팅으로 넘기기
- 드래그 툴바, 캡처 툴바, 노트 블록 메뉴에 **"Claude에게 묻기"** 버튼을 둔다.
- 누르면 `room.sendToClaudeSession(data, {deliver: "stage"})`를 호출한다. 보내는 데이터는 `{label, paperTitle, page, section?, selectedText?, assetId?, noteBlockId?}`이고, 4KiB 안으로 자른다. 데이터는 채팅 입력창에 첨부로 올라가고, 사용자가 질문을 덧붙여 보낸다.
- `room.presence({paper, page, section})`로 지금 읽는 위치를 계속 공개한다.
- **대체 경로**: `room`을 쓸 수 없거나 보내기가 실패하면 `db`의 `state/now` 문서에 같은 내용을 쓴다. 그리고 "채팅에 '이거 설명해줘'라고 말하면 돼요"라는 안내를 띄운다. 채팅의 Claude는 그 문서를 읽는다.
- 페이지는 현재 쪽과 현재 절을 `state/now`에도 기록한다(쪽이 바뀌면 몇 초에 한 번 정도로 제한해서). 채팅의 Claude가 "지금 어디 읽고 있어?"를 알 수 있게 하려는 것이다.

### 6.5 채팅의 공부 진행 (paper-lens 스킬에 "공부 모드" 절차 추가)
- 사용자가 "이 논문 같이 읽자"나 "공부 모드" 같은 말을 하면 다음 순서로 진행한다.
  1. 논문 페이지가 없으면 지금처럼 만든다. PDF는 오래 남는 폴더(6.7절)에 둔다.
  2. Claude가 PDF를 직접 읽고 **절 목차**(번호, 제목, 시작 쪽)를 만든다. 이 목차를 `db`의 `outline` 문서에 저장한다. 페이지는 이 목차로 현재 절을 판단한다.
  3. **한 절씩** 쉽게 설명한다. 설명이 끝나면 "다음 절로 갈까요, 이 부분을 더 볼까요?"처럼 묻고 멈춘다.
  4. 채팅의 Claude는 메시지가 와야 움직인다. 쪽을 넘긴다고 혼자 말을 걸 수는 없다. 그래서 다음 설명은 두 가지 방법으로 시작한다(설계자 판단).
     - 사용자가 채팅에 "다음"이라고 말한다. Claude는 이때 `state/now`를 읽고, 사용자가 이미 더 앞서 읽었으면 그 절로 건너뛴다.
     - 페이지 위쪽에 **"▸ 이 절 설명 듣기"** 버튼을 둔다. 현재 절이 표시되고, 누르면 `sendToClaudeSession({...절 정보}, {deliver: "send"})`로 채팅에 바로 요청한다.
  5. 설명할 때는 `state/now`(현재 쪽, 절)와 노트 내용을 참고해서, 사용자가 이미 적은 것은 짧게 넘어간다.
  6. "노트에 넣어줘"라고 하면 `ArtifactData`로 노트 블록을 추가한다. 출처 표시는 `by: "claude"`다. 수식은 `math` 블록으로 넣는다.
- 세션이 바뀌어도 이어갈 수 있게, 각 절의 설명 요점(3~5줄)을 `db`의 `explanations/{sectionId}`에 남긴다. 페이지의 노트 탭 위에 작은 "Claude 설명 기록" 토글로 보여준다. 6.6절의 흩어짐 문제를 보완하려는 것이다.

### 6.6 데이터 구조 (db, 논문 페이지마다)
- `blocks/{blockId}`: `{type, text, order, page?, eq?, rects?, assetId?, by: "me"|"claude", createdAt, updatedAt}`. `rects`는 `quote` 블록의 PDF 형광펜 위치(쪽 기준 비율 좌표)다. `order`는 실수형 분수 순서다(두 블록 사이에 넣을 때 중간값을 쓴다).
- `state/now`: `{page, section, selection?, assetId?, updatedAt}`
- `outline/main`: `{sections: [{id, num, title, page}]}`
- `explanations/{sectionId}`: `{summary, updatedAt}`
- 규칙: 모든 경로는 `write: "owner"`로 한다(비공개 페이지라서 소유자만 쓴다). 쓰기는 블록 하나에 한 번씩, 바뀐 때만 하고, 입력 중에는 디바운스(0.6초 정도)를 건다.
- 기존 localStorage 노트(하이라이트는 `rects` 포함, 저장한 답변)는 처음 열 때 한 번 `blocks`로 옮긴다. 같은 artifact 주소에서만 옮길 수 있으므로, 기존 논문 페이지는 같은 URL로 업데이트한다(6.7절).

### 6.7 논문 파일 위치
- 스킬이 PDF를 `~/Papers/paper-lens/<slug>/paper.pdf`에 저장하고, `paper.json`(제목, 출처, artifact URL)도 같은 폴더에 둔다. 같은 논문을 다시 열면 이 폴더와 기존 artifact를 다시 쓴다.
- Artifact 올리기는 작업 폴더나 스크래치패드 안의 파일만 받는다. 그래서 올릴 때마다 `~/Papers/...`의 파일을 스크래치패드로 복사해서 올린다(설계자 판단). 이미 있는 논문 페이지는 `paper.json`의 URL로 **같은 주소에 업데이트**한다. Attention과 BERT 시험 페이지도 같은 URL로 새 버전을 올린다. PDF 원본은 스킬이 다시 받아서 `~/Papers`에 둔다.

### 6.8 내보내기
- 노트 탭에서 "Markdown 받기"(downloads 기능)와 "복사"를 제공한다. 수식은 `$...$`와 `$$...$$` 그대로 내보내서 Obsidian이나 노션 가져오기와 호환되게 한다. 이미지는 `![](에셋 URL)`로 넣는다.

### 6.9 선언할 capability
`sample: {images: true}`, `downloads: true`, `db: {rules: [...]}`, `user: {}`, `assets: {}`, `room: {}`.

## 7. 설계자에게 맡기는 것
- 화면 디자인(색, 간격, 블록 손잡이 모양)은 기존 Paper Lens 스타일을 따른다.
- MathJax 정확한 버전, 블록 편집기 세부 키 동작, 분수 순서 재정렬 방식.
- `state/now` 쓰기 빈도, 절 판단 방법(목차의 시작 쪽 기준).
- 기존 논문 페이지(Attention, BERT)를 새 버전으로 다시 올리는 방법.

## 8. 확인이 필요한 위험
- `room.sendToClaudeSession`과 presence 전달이 이 사용자의 Claude 앱(Code 탭, 페이지가 채팅 옆에 열린 상태)에서 실제로 되는지는 만들어서 확인해야 한다. 안 되면 6.4절의 대체 경로(`state/now` + 채팅에 말하기)가 기본 경로가 된다.
- `ArtifactData`로 쓴 블록이 열려 있는 페이지에 실시간으로 반영되는지 확인해야 한다.
